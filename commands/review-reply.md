# Отработка ревью

Сначала прочитай `${CLAUDE_PLUGIN_ROOT}/refs/style.md`.

## Что собрать

1. Ссылка из `$ARGUMENTS`. Нет ссылки, спроси одной строкой и остановись.
2. Разбери хост, проект и номер.
3. GitLab, путь `/-/merge_requests/<iid>`.
   1. Треды `glab api --hostname <хост> "projects/<группа%2Fпроект>/merge_requests/<iid>/discussions?per_page=100" --paginate`.
   2. Бери только треды, у которых первая заметка `resolvable: true` и `resolved: false`. Пропускай `system: true`.
   3. Ветка MR `glab api --hostname <хост> "projects/<группа%2Fпроект>/merge_requests/<iid>"`, поле `source_branch`.
4. GitHub, путь `/pull/<n>`.
   1. Нет `gh`, скажи `brew install gh && gh auth login` и остановись.
   2. Треды через `gh api graphql` запросом `repository(owner, name) { pullRequest(number) { headRefName reviewThreads(first: 100) { nodes { isResolved path line comments(first: 50) { nodes { author { login } body } } } } } }`. Бери `isResolved: false`.
5. Ветка MR не совпадает с `git rev-parse --abbrev-ref HEAD`, скажи одной строкой и остановись.
6. Незакрытых тредов нет, скажи одной строкой и остановись.
7. По каждому треду открой текущий код в месте комментария. Цитата в треде могла устареть.
8. Подтяни `AGENTS.md`, `CLAUDE.md` и профильные `docs/`, по ним оценивай спорные замечания.

## План

1. По каждому треду три строки.
   1. `файл:строка, автор`.
   2. Суть простым языком, 1 по 2 предложения. Что заметил ревьюер и чем это грозит.
   3. Решение. Правлю и как, или не правлю и почему, или нужен вопрос ревьюеру.
2. Не соглашайся молча. Бага нет, поведение задумано или ревьюер не видел контекста, так и скажи с причиной из кода.
3. Покажи план и жди ок. До ок код не трогай.

## Правки

1. После ок правь только то, о чем треды.
2. Не коммить, не пушь, не резолвь треды, ничего не пиши в MR.

## Ответы

По каждому треду в порядке плана.

```
src/auth/auth.service.ts:42, ivan.petrov
Поправил, обернул запись токена и сессии в одну транзакцию.
```

1. Одно предложение, первое лицо, прошедшее время. Примеры «Поправил, вынес проверку в guard.», «Оставил так, значение уже проверяет валидатор в DTO.», «Не понял, имеется в виду кэш на клиенте или на сервере?»
2. Язык как у комментария ревьюера.
3. Без благодарностей, без «отличное замечание», без эмодзи, без ссылок на файлы внутри ответа.
4. Правка завязана на неочевидную специфику, допиши второе короткое предложение.

## Стиль

Правила из `${CLAUDE_PLUGIN_ROOT}/refs/style.md`. Перед отправкой проверь текст ответов отдельно.
