# Механика скиллов

Адаптировано из mattpocock/skills (MIT), `skills/productivity/writing-for-agents/SKILL-MECHANICS.md`.

Ветка [`writing-for-agents`](SKILL.md) для случая, когда документ это скилл. Фронтматтер, выбор способа вызова и скиллы-маршрутизаторы. Все остальное о том, как его писать, лежит в общей справке `SKILL.md`.

## Вызов

Два варианта, которые размениваются между двумя нагрузками.

1. **Скилл с вызовом моделью** хранит `description`, поэтому агент может запустить его сам, и другие скиллы могут до него дойти. Человек по-прежнему может вызвать его по имени. Вызов моделью всегда _включает_ доступ человека, описание только добавляет обнаружение агентом и ничего не отнимает у человека. Описание это верхний указатель скилла, и он вынужденно загружен всегда. Постоянная нагрузка на контекст в обмен на обнаружимость. Скилл с вызовом моделью, состоящий целиком из справки, еще и удобный дом для общей справки. Другой скилл может его вызвать, так что справка, нужная нескольким скиллам, живет в одном месте. Механика. Не ставь `disable-model-invocation` и пиши описание для модели с ветками срабатывания (правила про указатели из `SKILL.md` действуют полностью).
2. **Скилл с вызовом человеком** убирает описание из досягаемости агента. Запустить его может только человек, набрав имя, и никакой другой скилл. Нагрузка на контекст нулевая, но растет когнитивная, ты сам индекс и должен помнить, что скилл есть. Механика. Поставь `disable-model-invocation: true`, тогда `description` становится описанием для человека, одной строкой и без списка триггеров.

Выбирай вызов моделью, только если агент должен дойти до скилла сам или до него должен дойти другой скилл. Если он запускается только руками, делай вызов человеком и не плати нагрузкой на контекст.

Общая справка, которая нужна двум скиллам с вызовом человеком, не может жить ни в одном из них. Без описаний ни один не может запустить другой. Вынеси ее в обычный файл вне системы скиллов, во внешнюю справку, на которую может сослаться любой скилл.

## Деление по способу вызова

Разрез по способу вызова (разрез по последовательности описан в `SKILL.md`). Отделяй скилл с вызовом моделью, когда есть отдельное ведущее слово, которое должно запускать его само по себе (слово, которое ты реально пишешь в промптах), или когда до него должен дойти другой скилл. За новое постоянно загруженное описание платишь нагрузкой на контекст, поэтому независимый доступ должен того стоить.

## Скиллы-маршрутизаторы

Когда скиллов с вызовом человеком становится больше, чем ты можешь запомнить, накопленную когнитивную нагрузку лечит **скилл-маршрутизатор**. Это один скилл с вызовом человеком, который называет остальные и когда к какому идти, и человеку надо помнить один скилл вместо многих. Он может только подсказать, но не запустить их. У скиллов с вызовом человеком нет описаний, поэтому до них не дойдет никто, кроме человека.
