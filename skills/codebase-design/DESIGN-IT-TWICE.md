# Спроектируй дважды

Адаптировано из mattpocock/skills (MIT), `skills/engineering/codebase-design/DESIGN-IT-TWICE.md`.

Когда человек хочет посмотреть альтернативные интерфейсы для выбранного кандидата на углубление, используй параллельных субагентов. Идея из «Design It Twice» Оустерхаута. Первая идея редко бывает лучшей.

Словарь из `${CLAUDE_PLUGIN_ROOT}/refs/codebase-design.md`: **модуль**, **интерфейс**, **шов**, **адаптер**, **рычаг**.

## Процесс

### 1. Очерти пространство задачи

До запуска субагентов напиши для человека объяснение задачи по выбранному кандидату.

1. Ограничения, которым должен удовлетворять любой новый интерфейс.
2. Зависимости, на которые он опирается, и их категории (см. `DEEPENING.md`).
3. Грубый набросок кода, чтобы ограничения стали конкретными. Это не предложение, а опора для разговора.

Покажи это человеку и сразу переходи к шагу 2. Человек читает и думает, пока субагенты работают.

### 2. Запусти субагентов

Запусти параллельно 3 или больше субагентов. Каждый должен выдать **радикально другой** интерфейс углубленного модуля.

Каждому дай отдельный технический бриф: пути файлов, детали связности, категорию зависимостей из `DEEPENING.md`, что стоит за швом. Бриф не зависит от объяснения для человека из шага 1. Каждому свое ограничение.

1. Агент 1. «Минимизируй интерфейс, максимум 1 до 3 точек входа. Максимальный рычаг на точку входа.»
2. Агент 2. «Максимальная гибкость, поддержи много сценариев и расширение.»
3. Агент 3. «Оптимизируй под самого частого вызывающего, сделай случай по умолчанию тривиальным.»
4. Агент 4, если уместно. «Построй вокруг портов и адаптеров для зависимостей через шов.»

В бриф положи словарь из `refs/codebase-design.md` и словарь из `GLOSSARY.md`, если он есть в проекте, чтобы субагенты называли вещи одинаково.

Каждый субагент выдает.

1. Интерфейс: типы, методы, параметры, а еще инварианты, порядок вызовов, режимы ошибок.
2. Пример использования вызывающим.
3. Что реализация прячет за швом.
4. Стратегию зависимостей и адаптеры (см. `DEEPENING.md`).
5. Компромиссы: где рычаг большой, где слабый.

### 3. Покажи и сравни

Показывай варианты по очереди, чтобы человек успел осмыслить каждый, потом сравни их текстом. Сравнивай по **глубине** (рычаг на интерфейсе), **локальности** (где собираются изменения) и **месту шва**.

После сравнения дай свою рекомендацию, какой вариант сильнее и почему. Если части разных вариантов хорошо сочетаются, предложи гибрид. Будь категоричен, человеку нужна сильная позиция, а не меню.
