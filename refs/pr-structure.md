# Структура описания MR и PR

Источники. Google eng-practices (CL descriptions), шаблоны Kubernetes, React, GitLab, wshobson `pr-enhance`.

## Заголовок

1. `type(scope): subject` по Conventional Commits. `type` из `feat fix refactor docs test chore perf build ci`.
2. До 72 символов, повелительное наклонение, без точки в конце.
3. Номер задачи из ветки (`ABC-123`) в scope или в начале subject, если так принято в репозитории. Смотри последние MR.

## Тело

1. **Зачем.** 1 по 3 предложения о проблеме или контексте. Ссылка на задачу, `Closes #123` для GitHub или ключ JIRA.
2. **Что сделано.** 3 по 7 пунктов про поведение, а не про файлы. Рефакторинг отдельным последним пунктом.
3. **Как проверить.** Конкретные шаги или команды. Для бэка запрос или тест, для фронта где кликнуть.
4. **Скриншоты.** Только если менялся UI. Оставь место `<!-- скриншот до и после -->`.
5. **На что смотреть.** Только если реально есть. Миграции, breaking changes, новые env, флаги, неочевидные решения, места для внимательной проверки.

## Правила

1. Описание должно быть понятно через год без открытого кода.
2. Не пересказывай названия коммитов.
3. Не оценивай свою работу.
4. Пустые секции не пиши.
