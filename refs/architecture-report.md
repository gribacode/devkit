# Формат HTML-отчета

Адаптировано из mattpocock/skills (MIT), `skills/engineering/improve-codebase-architecture/HTML-REPORT.md`.

Отчет об архитектуре это один самодостаточный HTML-файл во временном каталоге ОС. Tailwind и Mermaid берутся с CDN. Mermaid надежно рисует графы, а собранные вручную div и встроенный SVG рисуют более авторские картинки (диаграммы массы, разрезы). Смешивай их. Если все рисовать Mermaid, отчет начнет выглядеть шаблонно.

## Каркас

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <title>Архитектура {{имя репозитория}}</title>
    <script src="https://cdn.tailwindcss.com"></script>
    <script type="module">
      import mermaid from "https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs";
      mermaid.initialize({ startOnLoad: true, theme: "neutral", securityLevel: "loose" });
    </script>
    <style>
      /* маленький свой слой для того, что Tailwind не покрывает чисто:
         пунктир швов, стрелки, похожие на нарисованные от руки, и т.п. */
      .seam { stroke-dasharray: 4 4; }
      .leak { stroke: #dc2626; }
      .deep { background: linear-gradient(135deg, #0f172a, #1e293b); }
    </style>
  </head>
  <body class="bg-stone-50 text-slate-900 font-sans">
    <main class="max-w-5xl mx-auto px-6 py-12 space-y-12">
      <header>...</header>
      <section id="candidates" class="space-y-10">...</section>
      <section id="top-recommendation">...</section>
    </main>
  </body>
</html>
```

## Шапка

Имя репозитория, дата и компактная легенда. Сплошная рамка это модуль, пунктир это шов, красная стрелка это протечка, толстая темная рамка это глубокий модуль. Без вводного абзаца, сразу кандидаты.

## Карточка кандидата

Вес несут схемы. Текста мало, он простой и использует термины словаря из `${CLAUDE_PLUGIN_ROOT}/refs/codebase-design.md` без церемоний.

Каждый кандидат это один `<article>`.

1. **Заголовок.** Коротко, называет углубление, например «Схлопнуть прием заказов».
2. **Ряд бейджей.** Сила рекомендации (`Сильно` изумрудный, `Стоит изучить` янтарный, `Спекулятивно` серый) и тег категории зависимостей (`в процессе`, `локально подменяемые`, `порты и адаптеры`, `мок`).
3. **Файлы.** Моноширинный список, `font-mono text-sm`.
4. **Схема До и После.** Центр карточки. Две колонки рядом, паттерны ниже.
5. **Проблема.** Одно предложение, что болит.
6. **Решение.** Одно предложение, что меняется.
7. **Выгода.** Пункты по 6 слов максимум. Например «Тесты бьют в один интерфейс», «Логика цен перестает протекать», «Удалить 4 мелкие обертки».
8. **Пометка про ADR**, если нужна. Одна строка в янтарной плашке.

Без абзацев объяснений. Если схеме нужен абзац, чтобы ее поняли, перерисуй схему.

## Паттерны схем

Выбирай паттерн под кандидата и смешивай их. Не делай все схемы одинаковыми, разнообразие часть смысла.

### Граф Mermaid (рабочая лошадка для зависимостей и потока вызовов)

Используй `flowchart` или `graph` Mermaid, когда суть в том, что X вызывает Y, тот вызывает Z, и посмотри на этот беспорядок. Оберни его в карточку со стилями Tailwind, чтобы он не выглядел чужеродным. Через `classDef` покрась ребра протечек в красный, а глубокий модуль в темный. Диаграммы последовательности хорошо показывают «до 6 запросов туда и обратно, после 1».

```html
<div class="rounded-lg border border-slate-200 bg-white p-4">
  <pre class="mermaid">
    flowchart LR
      A[OrderHandler] --> B[OrderValidator]
      B --> C[OrderRepo]
      C -.leak.-> D[PricingClient]
      classDef leak stroke:#dc2626,stroke-width:2px;
      class C,D leak
  </pre>
</div>
```

### Рамки и стрелки вручную (когда раскладка Mermaid мешает)

Модули это `<div>` с рамками и подписями. Стрелки это встроенные SVG `<line>` или `<path>`, абсолютно позиционированные поверх относительного контейнера. Бери это, когда схема После должна выглядеть как один глубокий модуль с толстой рамкой и приглушенными внутренностями. Mermaid не нарисует это с нужным весом.

### Разрез (для слоистой мелкости)

Сложи горизонтальные полосы (`h-12 border-l-4`), чтобы показать слои, через которые проходит вызов. До это 6 тонких слоев, каждый ничего не делает. После это 1 толстая полоса с подписью объединенной ответственности.

### Диаграмма массы (для «интерфейс шириной с реализацию»)

Два прямоугольника на модуль, один про площадь интерфейса, другой про реализацию. До прямоугольник интерфейса почти такой же высокий, как реализация (мелкий модуль). После интерфейс низкий, реализация высокая (глубокий модуль).

### Схлопывание графа вызовов

До это дерево вызовов функций во вложенных рамках. После то же дерево схлопнуто в одну рамку, а ставшие внутренними вызовы показаны внутри бледным.

## Стиль

1. Ближе к журнальной верстке, чем к корпоративному дашборду. Много воздуха. Для заголовков можно serif (`font-serif` хорошо сочетается со stone и slate).
2. Цвета скупо. Один акцент (emerald или indigo), красный для протечек, янтарный для предупреждений.
3. Схемы высотой около 320px, чтобы До и После стояли рядом без прокрутки.
4. Подписи модулей внутри схем через `text-xs uppercase tracking-wider`, чтобы читались как схема, а не как интерфейс приложения.
5. Скрипты только Tailwind с CDN и импорт Mermaid. В остальном отчет статичный, без кода приложения и интерактива сверх рендера Mermaid.

## Главная рекомендация

Одна крупная карточка. Имя кандидата, одно предложение почему, якорная ссылка на его карточку. Все.

## Тон

Простой русский, сжато, но архитектурные существительные и глаголы берутся прямо из словаря `refs/codebase-design.md`. Краткость не повод от него отходить.

**Используй ровно эти слова.** Модуль, интерфейс, реализация, глубина, глубокий, мелкий, шов, адаптер, рычаг, локальность.

**Не подменяй.** Компонент, сервис, юнит вместо модуля. API, сигнатура вместо интерфейса. Граница вместо шва. Слой, обертка вместо модуля, когда имеешь в виду модуль.

**Формулировки в нужном стиле.**

1. «Модуль приема заказов мелкий, интерфейс почти совпадает с реализацией.»
2. «Цены протекают через шов.»
3. «Углубить. Один интерфейс, одно место для тестов.»
4. «Два адаптера оправдывают шов. HTTP в проде, в памяти в тестах.»

**Пункты выгоды** называют выигрыш словами словаря. *«локальность, баги собираются в одном модуле»*, *«рычаг, один интерфейс на N мест вызова»*, *«интерфейс сжимается, реализация поглощает обертки»*. Не пиши *«проще поддерживать»* или *«чище код»*, этих слов нет в словаре, и они не окупают свое место.

Без оговорок, без раскачки и без «стоит отметить, что». Предложение может быть пунктом, делай пунктом. Пункт можно вырезать, вырезай. Термина нет в словаре, сначала поищи подходящий там, а потом уже придумывай новый.
